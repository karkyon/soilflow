## 4. 並行稼働

| 項目 | 内容 |
|---|---|
| 期間 | 2月下旬から1〜2週間（P18） |
| やり方 | 受付は紙の日報と画面の両方に記入する。伝票は電子サインで発行し、紙の伝票も従来どおり（お客さまへの説明を兼ねる） |
| 毎日の照合 | 本社が、紙の日報の会社ごとの台数と、画面の台数を照合する。違いは原因（記入漏れ・誤り）を記録して直す |
| 月の照合 | 期間中の便で試しに締め、従来の方法で作った請求書の金額と比べる |
| 本稼働の判断 | 最後の3営業日で台数の違いが0、試しの締めの金額が一致、重大な不具合が0 → 本稼働。満たさなければ延長 |
| freee | 並行稼働の間は本番の freee に登録しない（試験用の事業所だけ）。本稼働の最初の締めから本番に登録 |

## 5. 不具合の管理

| 重大度 | 例 | 対応 |
|---|---|---|
| 重大 | 金額の誤り、データが消える、freee に誤った登録 | すぐ直す。直るまで次の段階に進まない |
| 高 | 業務の流れが止まる（伝票を発行できない など） | 当日〜翌日に直す |
| 中 | 回避の方法がある不具合 | その段階のうちに直す |
| 低 | 表示の乱れ・文言 | 本稼働までに直す（または保守で） |

不具合は GitHub の Issue で管理し、試験の ID・再現の手順・重大度を書きます。
