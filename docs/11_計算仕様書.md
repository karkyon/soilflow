## 1. 基本の決まり

| No | 決まり |
|---|---|
| 1 | 金額はすべて整数（円）で計算する。小数が出るのは消費税だけで、4.5 の端数処理で整数にする |
| 2 | 単価は1台あたりの税抜の金額。お客さまごとの単価はない【確定 D-09】 |
| 3 | 日付は日本時間の「年-月-日」で扱う。便の日付＝日報の日付 |
| 4 | 計算は画面・DB・API から独立した関数（`packages/billing`）で行い、API・バッチ・モックアップで同じものを使う |
| 5 | 計算結果は、請求書の作成時にデータベースへ書き残す（後で単価表を変えても、作成済みの請求書の金額は変わらない） |

## 2. 台数

| 項目 | 計算 |
|---|---|
| 行の台数 | その行の便のうち、状態が「有効」（取消でない）のものの数 |
| 客先の台数（日報の右端） | その日の、その客先のすべての行の台数の合計【回答待ち Q-26】 |
| 日計（本日 N台） | その日のすべての行の台数の合計 |

1便＝1台です。同じ車が受入れと納品を同時に行う場合は、品名の違う2行に記入し、それぞれ1台と数えます【回答待ち Q-05】。

### 2.1 便の時刻

- 便の時刻は「時:分」で記録する（秒は持たない）。
- 今の時間帯のマスをクリックした場合：時刻＝クリックした時点の現在時刻（サーバーの時刻ではなく、受付PCの画面で押した瞬間の時刻をサーバーで日本時間に直したもの。PCの時計のずれが5分を超えるときはサーバーの時刻を使い、画面に知らせる）。
- 過去の時間帯のマスの場合：時刻＝そのマスの時＋入力した分。

### 2.2 時間帯の列

- 便を表示する列＝便の時（0〜23）を、設定の最初の列と最後の列の範囲に収めたもの。
- 例：設定が7〜16時で便が6:50なら7の列、17:10なら16の列に表示する（記録する時刻は変えない）。

## 3. 便の品目・単価・請求先

### 3.1 便の品目（印による切り替え）

```
便の品目 ＝ 印の切り替え規則に（便の印, 行の品目）があれば その切り替え先
            なければ 行の品目
```

- 印がない便は、行の品目のまま。
- 規則は印マスタ（FR-MST-08）で持つ。初期値は 02 要件定義書 5.8 の表。
- 行の品目を変えたときや、規則を変えたときは、まだ請求書が送信済みになっていない便の品目を計算し直す（送信済の便は変えない）。

例（提案書 P08 Q1）：行「305 残土10t」の 9時・10時（草）・11時の便 → 9時と11時は建設発生土1〜2種、10時は建設発生土（草根混）1〜2種。

### 3.2 単価

```
適用する単価表 ＝ 適用開始日 ≦ 便の日付 のうち、適用開始日が最も新しい単価表
便の単価       ＝ 適用する単価表の（便の品目, 行の車格）の金額
```

- 単価表は、適用開始日ごとに品目×車格の全部の金額を持つ（改定のときは前の表を写して直す）。
- 該当する金額がない便は「単価なし」とし、その請求先の請求書は作らない（4.6）。
- 価格改定の切り替えは便の日付（来場日）で行う【回答待ち Q-34】。月の途中で改定しても、同じ請求書の中で改定前と改定後の単価が別の明細行になる。

### 3.3 価格表との照合（参考値）

単価表の画面（SCR-56）では、次の参考値を並べて表示し、単価と違えば印を付けます。

```
参考値 ＝ 四捨五入（㎥単価 × 車格の容量）＋（4t車以下 かつ 品目に積込料加算があれば 積込料加算）
```

| 車格 | 10t | 8t | 6t | 4t | 3t | 2t | 1t |
|---|---|---|---|---|---|---|---|
| 容量（㎥） | 5.5 | 4.4 | 3.3 | 2.2 | 1.7 | 1.1 | 0.6 |
| 4t車以下 | | | | ○ | ○ | ○ | ○ |

2023年4月改定の価格表の ㎥単価 がある11品目×7車格＝77の金額は、すべてこの式と1円も違わずに一致することを確認しています（正解データ G-04）。ストックヤード搬出は積込料だけの品目のため、参考値はありません。請求に使うのは単価表の金額で、参考値は使いません【回答待ち Q-02】。

### 3.4 便の請求先

```
① 便が伝票に含まれ、その伝票が取消でなければ   → 伝票の請求先
② ①でなく、行の現場に既定の請求先があれば     → 現場の既定の請求先
③ それ以外                                       → 客先の既定の請求先
```

- 客先を登録すると、同じ名前の請求先を作って客先の既定の請求先にする（提案書 P15 ケースA）。客先の既定の請求先は必ずある。
- ケースB（運搬会社が来場し請求は元請）＝客先の既定の請求先を元請にする。
- ケースC（現場で請求先が変わる）＝現場の既定の請求先を設定する。
- ケースD（その日だけの例外）＝伝票の請求先を選び直す。

## 4. 請求書

### 4.1 請求期間

請求先ごとの締め日（0＝月末、1〜28 の日）で決めます。

```
対象月 M の締めの日 ＝ 締め日が0なら M の末日、それ以外は M の「締め日」日
                       （その月にない日は末日）
請求期間の終わり   ＝ 対象月 M の締めの日
請求期間の始まり   ＝ 前の月の締めの日の翌日
```

| 締め日 | 対象月 | 請求期間 |
|---|---|---|
| 月末（0） | 2026-02 | 2026-02-01 〜 2026-02-28 |
| 20日 | 2026-02 | 2026-01-21 〜 2026-02-20 |
| 15日 | 2026-01 | 2025-12-16 〜 2026-01-15 |
| 28日 | 2028-03 | 2028-02-29 〜 2028-03-28（うるう年） |

締め日に登録できるのは「月末」と1〜28日です（29〜31日はうるう年・小の月で期間がずれるため）【回答待ち Q-08】。

### 4.2 対象の便

請求先ごとに、次をすべて満たす便を集めます。

1. 状態が有効（取消でない）
2. 3.4 で決まる請求先が、その請求先
3. 便の日付が請求期間に入る
4. 別の有効な請求書（取消でないもの）にまだ含まれていない

4 を満たさない便は「請求済」として飛ばし、締めの前の確認（FR-BIL-04）に出します。

### 4.3 請求日・入金期日

```
請求日   ＝ 請求期間の終わりの日（請求書ごとに変更可）
入金期日 ＝ 請求期間の終わりの月から「支払月」か月後の「支払日」（0＝末日。その月にない日は末日）
```

| 請求期間の終わり | 支払月 | 支払日 | 入金期日 |
|---|---|---|---|
| 2026-02-28 | 1（翌月） | 末日 | 2026-03-31 |
| 2026-02-20 | 1（翌月） | 10日 | 2026-03-10 |
| 2026-01-31 | 1（翌月） | 31日 | 2026-02-28 |
| 2026-11-30 | 2（翌々月） | 末日 | 2027-01-31 |

### 4.4 明細

便を次の組合せでまとめ、1つの組合せを明細の1行にします。

```
組合せ ＝（現場, 便の品目, 行の車格, 単価）
台数   ＝ 組合せに入る便の数
金額   ＝ 単価 × 台数
```

並び順は、現場の読みがな順 → 品目の表示順 → 車格の表示順 → 単価の小さい順です。単価を組合せに入れているのは、月の途中の価格改定で同じ品目・車格に2つの単価があるときに、行を分けるためです。

### 4.5 小計・消費税・合計

```
小計     ＝ 明細の金額の合計（税抜）
消費税額 ＝ 端数処理（小計 × 税率 ÷ 100）
合計     ＝ 小計 ＋ 消費税額
```

- 端数処理は請求書ごと・税率ごとに1回だけ行います（インボイス制度の決まり。明細の行ごとに端数処理して足し合わせない）。
- 端数処理の方法は設定で「切り捨て（初期値）・四捨五入・切り上げ」から選びます【回答待ち Q-06】。
- 税率は 10%（標準税率）だけです。軽減税率の品目はありません。
- 計算は整数で行います（小計×税率 を 100 で割る前に端数を出さない）。

| 小計 | 切り捨て | 四捨五入 | 切り上げ |
|---|---|---|---|
| 68,750 | 6,875 | 6,875 | 6,875 |
| 3,705 | 370 | 371 | 371 |

今の価格表の金額はすべて10円単位のため、端数が出るのは単価表を変えたときだけです。

### 4.6 請求書を作らない場合

| 場合 | 扱い |
|---|---|
| 対象の便に「単価なし」が1つでもある | その請求先の請求書を作らず、締めの前の確認と締めの結果に出す |
| 対象の便がない | 請求書を作らない（0円の請求書は作らない） |
| 請求先が無効 | 作らない。無効の請求先に便が残っていれば警告する |

### 4.7 請求書番号

```
請求書番号 ＝ "SF-" ＋ 請求期間の終わりの年の下2桁 ＋ 月2桁 ＋ "-" ＋ 連番3桁
```

- 連番は、請求期間の終わりの月ごとに、請求先の読みがな順で 001 から付けます。同じ月にあとから作る請求書（追加の締め・再発行）は、その月の最大の番号の次から付けます。
- 例：2026年2月締め → SF-2602-001、SF-2602-002 …【回答待ち Q-09】

### 4.8 作り直し・取消・再発行

| 操作 | できる状態 | 計算 |
|---|---|---|
| 作り直す | 作成済・要再確認・確認済 | 同じ請求先・同じ請求期間で 4.2〜4.5 をやり直す。番号は変えない |
| 取消 | 送信済・送信エラー | 請求書を「取消」にし、含まれていた便を 4.2 の 4 から外す（再び請求の対象になる） |
| 取消して再発行 | 送信済・送信エラー | 取消のあと、同じ請求先・同じ請求期間で新しい番号の請求書を作る。元の番号を「元の請求書」として記録する |

## 5. freee の取引の明細

請求書を freee会計に登録するときの、取引の明細の作り方です（FR-FRE-14）。

### 5.1 まとめ方

```
組合せ ＝（勘定科目, 税区分, freee の品目）  ← 品目マスタの対応付け（FR-MST-05・FR-FRE-08）
組合せの税抜金額 ＝ その組合せに入る請求書の明細の金額の合計
```

- 並び順は、組合せに入る最初の請求書の明細の順です。
- freee の明細は1取引100行までです。100を超えたら登録せず「要対応」にします（今の品目の数では起こりません）。
- 対応付けがない品目が1つでもあれば、登録せず「要対応」にします。

### 5.2 消費税額の配り方

freee の明細には税込の金額（amount）と消費税額（vat）を渡します。請求書の消費税は請求書全体で1回だけ端数処理しているため、明細ごとに計算すると合計が1円ずれることがあります。次の方法で必ず一致させます。

```
1. 各組合せの消費税額 ＝ 4.5 と同じ端数処理（組合せの税抜金額 × 税率 ÷ 100）
2. 差 ＝ 請求書の消費税額 − 1 の合計
3. 差が 0 になるまで、税抜金額の大きい組合せから順に 1円ずつ足す（差が負なら引く）
   税抜金額が同じなら、並び順の早いものから
4. 各組合せの税込金額 ＝ 税抜金額 ＋ 消費税額
```

これで、明細の税込金額の合計＝請求書の合計、消費税額の合計＝請求書の消費税額になります。

例（正解データ G-02）：明細 1,235円（品目 a）と 1,235円（品目 b）、請求書の消費税額 247円（2,470円の10%）

| 組合せ | 税抜 | 1 の消費税 | 差の配分 | 消費税 | 税込 |
|---|---|---|---|---|---|
| a | 1,235 | 123 | ＋1 | 124 | 1,359 |
| b | 1,235 | 123 | | 123 | 1,358 |
| 合計 | 2,470 | 246 | 差 1 | 247 | 2,717 |

freee の事業所の経理方式（税込経理・税抜経理）によって、freee 側の表示は変わりますが、渡す値は同じです。経理方式は【回答待ち Q-18】で確認し、結合試験（AC-08）で一致を確かめます。

## 6. 集計

集計（FR-AGG-03）の金額は、請求書を作る前でも見られるように、3.1〜3.4 と 4.4 の決まりでその場で計算します。

| 項目 | 計算 |
|---|---|
| 台数 | 2章と同じ |
| 金額（税抜） | 便の単価の合計（単価なしの便は金額に入れず、件数を別に表示する） |
| 消費税 | 集計では計算しない（請求書ごとに計算するため） |

送信済の請求書に含まれる便は、請求書に書き残した単価で集計します（あとで単価表を変えても変わらない）。
