## 4. 番号の付け方

| 記号 | 対象 | 例 |
|---|---|---|
| BR-nn | 業務要件 | BR-03 伝票発行 |
| FR-xxx-nn | 機能要件（xxx は機能の区分） | FR-RCV-04 便の記録 |
| NFR-nn | 非機能要件 | NFR-01 応答時間 |
| SCR-nn | 画面 | SCR-10 受入日報 |
| RPT-nn | 帳票 | RPT-03 請求書 |
| IF-nn | 外部とのつなぎ口（インターフェイス） | IF-01 freee会計API |
| AC-nn | 受入条件（お客さまに検収していただく条件） | AC-05 |
| Q-nn | 未決事項（お客さまへの確認待ちを含む） | Q-01 |
| D-nn | 決定事項 | D-01 |
| CHG-nnn | 変更要求（要件定義の確定後に範囲・仕様を変えるもの） | CHG-001 |

機能要件の区分は次のとおりです。

| 区分 | 意味 |
|---|---|
| RCV | 受入日報（Receive） |
| SLP | 伝票（Slip） |
| SGN | 電子サイン（Sign） |
| AGG | 集計（Aggregate） |
| BIL | 請求（Billing） |
| MAL | メール送信（Mail） |
| FRE | freee会計連携（freee） |
| MST | マスタ管理（Master） |
| CMN | 共通（Common：ログイン・利用者・操作履歴・設定） |

## 5. 記述の状態の表し方

要件・設計の各項目に、次の印を付けます。06 のモックアップの「仕様メモ」でも同じ印を使います。

| 印 | 意味 |
|---|---|
| 【確定】 | お客さまとの打合せ・提案書で決まった事項 |
| 【設計案】 | 当方からの提案。お客さまの承認前 |
| 【回答待ち Q-nn】 | お客さまに確認中。番号は台帳の未決事項 |
| 【デモ】 | モックアップのための架空の値 |
| 【実例】 | お客さまからいただいた資料（日報・価格表）の値 |

## 6. 版の管理

- すべての資料は Git（変更履歴を残す仕組み）で管理し、GitHub のリポジトリに置きます。claude.ai のプロジェクトにも同じものを置きます。
- 版は「主番号.副番号」で表します。お客さまに提出する版で主番号を上げます。
- 要件定義書の確定（AC：要件定義工程の完了）以降の範囲・仕様の変更は、台帳に CHG 番号を取って記録し、影響する資料をまとめて更新します。

## 8. Word 版

`word/` に、すべての Markdown の資料を Word（.docx）にしたものがあります。図（Mermaid）は画像にして入れています。Markdown が正本で、Word はお客さまへの提出・印刷用です。資料を直したら Word を作り直します（`python3 tools/build_word.py <mmdc> <puppeteer の設定>`）。
