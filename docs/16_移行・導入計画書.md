## 2. 移行するもの

現行は紙のため、過去の日報・伝票・請求書のデータは移行しません。本稼働の日からの記録を SoilFlow で始めます。

| 対象 | 移行する | 方法 | 時期 |
|---|---|---|---|
| 品目・車格・単価表・印 | する | `spec/seed.sql`（価格表から作成済み）。Q-01〜Q-04 の回答で日報表記を直す | 1月上旬 |
| 客先・現場・請求先・車番 | する | お客さまの資料から CSV（3章）を作り、一括登録（FR-MST-10） | 1月上旬（資料は12月中にいただく） |
| 宛名と請求先が異なる客先・現場 | する | 客先・現場の「既定の請求先」に入れる（Q-22） | 同上 |
| 利用者・サイン端末 | する | 管理者が画面で登録（SCR-60） | 2月上旬 |
| 会社情報・請求書の文面・メールのひな形 | する | 設定の画面（SCR-62）。現行の請求書（Q-07）に合わせる | 1月中 |
| freee の連携・対応付け | する | 5章 | 1月中（試験用）、本稼働前（本番） |
| 過去の日報・伝票・請求書 | しない | 紙のまま保管（7年） | ― |
| 並行稼働中の便 | する | 並行稼働は本番の環境で行い、そのまま本稼働のデータにする | 2月下旬〜 |

## 3. マスタの CSV

ひな形は `reference/templates/` にあります（UTF-8 BOM 付き。Excel で開いて記入できます）。

| ファイル | 列 | 決まり |
|---|---|---|
| 客先.csv | 会社名・読みがな・既定の請求先・備考 | 読みがなはひらがな（日報の頭文字の絞り込みに使う）。既定の請求先が空なら同じ名前の請求先を作る |
| 現場.csv | 会社名・現場名・読みがな・既定の請求先 | 会社名は客先.csv の名前と同じにする。既定の請求先が空なら会社の既定を使う |
| 請求先.csv | 名称・読みがな・敬称・郵便番号・住所・送付先メール（宛先・CC）・締め日・支払月・支払日 | 締め日は 0（月末）か 1〜28。メールは「;」で区切る |
| 車番.csv | 会社名・車番・よく使う車格 | 車格は 10t・8t・6t・4t・3t・2t・1t |

取込の手順：

1. 取込の画面で CSV を選び、「確認だけ」（dryRun）で取り込む。
2. 誤り（必須の空欄・存在しない会社名・締め日の範囲外・重複）の一覧を見て、CSV を直す。
3. 誤りが0件になったら本番の取込を行う。
4. 本社の方に、客先・請求先の一覧を画面で見ていただき、名前・請求先・メールアドレスを確かめていただく。

## 9. うまくいかないときの戻し方

| 場面 | 戻し方 |
|---|---|
| 並行稼働中に重大な不具合 | 紙の日報・紙伝票を正として業務を続け、直ってから並行稼働をやり直す |
| 本稼働後に SoilFlow が使えない | 紙の日報・紙伝票に戻す（BR-13）。復旧後に画面へ入力し直す（17 3章） |
| 最初の締めで金額が合わない | 請求書を送らずに原因を調べる。必要なら従来の方法で請求し、SoilFlow の請求書は取り消す |
| freee の登録の誤り | 取消（または freee の画面で修正）。登録のしかたは「確認してから登録」のまま続ける |
